# AI Recommender Systems: companion code

Working code for the book *AI Recommender Systems*. Each chapter has its own folder, and every listing in the book is a short excerpt of a full, runnable file here.

The running example throughout the book is **Tesselo**, a fictional global platform with a shop, a video feed, ads and an AI assistant.

## Setup

You need Python 3.12 or later, because NumPy 2.5.4 (the tested version) does not support older versions of Python.

```bash
python -m venv .venv
source .venv/bin/activate        # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

To reproduce the book's printed output exactly, install the tested versions instead:

```bash
pip install -r requirements.txt -c constraints.txt
```

Tested with Python 3.13 and 3.14 and NumPy 2.5.4 (pinned in `constraints.txt`); Chapters 6 to 8 with Python 3.13, PyTorch 2.15.0 and faiss-cpu 1.15.1 (Chapter 7 needs PyTorch only), Chapter 8 with pyroaring 1.2.0 and LightGBM 4.7.0, Chapter 9 with PyTorch 2.15.0 and pyroaring 1.2.0, and Chapters 10 and 11 with PyTorch 2.15.0, SciPy 1.18.1 and pyroaring 1.2.0. Other versions may print a different final slate. Chapter 4's star-rating results come from SGD, which makes many small floating-point updates, so on a different processor their last decimal can differ slightly.

Chapter 6 needs PyTorch and Faiss; Chapter 7 needs PyTorch only (it imports Chapter 6's two-tower code, not Faiss); Chapter 8 needs PyTorch, pyroaring and LightGBM, and imports Chapters 6 and 7's code; Chapter 9 needs PyTorch and pyroaring, and imports Chapters 2 to 8's code, but not LightGBM; Chapter 10 needs the same and imports Chapters 2 to 9's code; Chapter 11 needs the same and imports Chapters 2 to 10's code. The tested versions of both publish wheels on PyPI for Linux and for macOS on Apple Silicon (macOS 14 or later). On Linux, `pip install torch` downloads the CUDA build, several gigabytes; the scripts use only the CPU, so you can install the smaller CPU build first:

```bash
pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt -c constraints.txt
```

On macOS, LightGBM needs an OpenMP runtime (`libomp.dylib`), which macOS does not include, and its wheel looks for one only in Homebrew's and MacPorts' folders. Without Homebrew or MacPorts you can use the copy that PyTorch's macOS wheel ships in its `lib` folder, by putting that folder on the library search path. `chapter_08/learning_to_rank.py` does this itself: if LightGBM cannot load, the script restarts once with `DYLD_LIBRARY_PATH` set to PyTorch's `lib` folder. macOS ignores `DYLD_LIBRARY_PATH` for Apple's own Python in `/usr/bin`, so use a Python from python.org, a virtual environment made from one, or conda. To set the path yourself, run:

```bash
DYLD_LIBRARY_PATH="$(python -c 'import os, torch; print(os.path.join(os.path.dirname(torch.__file__), "lib"))')" python chapter_08/learning_to_rank.py
```

If LightGBM still cannot load, the script skips LambdaMART and says so. That run reproduces everything except LambdaMART's rows in the two learning-to-rank tables, so it is a partial run, not a reproduction of every comparison.

Chapter 6's to Chapter 11's run times were measured on a two-core cloud machine (Intel Xeon at 2.10 GHz), and the numbers printed in the book are one reference run on that machine. On one machine the scripts repeat exactly, apart from timings: every random draw is seeded, and the scripts fix their thread counts (two for PyTorch and for NumPy's linear algebra, one for Faiss). Across machines, results can move, because processors and library builds add up floating-point numbers in different orders: PyTorch does not promise identical training on different platforms, and Faiss documents that its matrix operations are implemented differently on different processors, so they need not match exactly even on one thread. The results affected are those that depend on a trained two-tower model or, in Chapters 7 to 9, a trained ranker or sequence model, including the order of methods within one language, and the index recall of `vector_search.py`. Two external runs with the pinned versions (the first on an Apple Silicon Mac) gave, for example, hit@10 0.189 instead of 0.192, HNSW recall@10 0.883 instead of 0.900, and IVF-PQ recall@10 0.568 instead of 0.604 at nprobe 16. These are observed differences, not limits; another machine could differ by more. In the runs checked, none of the chapter's conclusions changed. The chapter gives standard errors for its close comparisons; read those before reading a small difference. Chapter 9's outputs start with a line naming the Python, NumPy and PyTorch versions and the machine they ran on, and its scripts break ties in a fixed order (by video or visit id), so that a tie is not resolved differently by different NumPy builds. Its standard errors come from resampling whole users, since one user's requests are not independent. Its longer scripts run each world in a process of its own, to keep memory down.

On macOS, the pip wheels of PyTorch and Faiss each bring their own copy of the OpenMP library, and a Python process that loads both stops with `OMP: Error #15`. No Chapter 6 script loads both: `vector_search.py` runs the PyTorch part (`embed_catalogue.py`) in a separate process.

Chapter 11's text vectors are not stored in this repository, because the file is over 100 MB. Make them once with `chapter_11/embed_texts.py`, which reads `chapter_11/texts_to_embed.tsv` and downloads three models from Hugging Face (about 1.5 GB in all). It needs sentence-transformers, which is not in `requirements.txt`, so use a separate environment:

```bash
cd chapter_11
python -m venv .venv-embed
.venv-embed/bin/pip install "sentence-transformers>=5,<6"
.venv-embed/bin/python embed_texts.py
```

It writes `chapter_11/text_embeddings.npz`, which the other Chapter 11 scripts read; they check that the file was made from this world's texts. The book's run used vectors made on the author's Mac. Vectors made on another machine, or with other library versions, can differ in their last digits, so a few of Chapter 11's results can differ in the fourth decimal place.
